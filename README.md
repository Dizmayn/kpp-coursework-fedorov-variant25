# Інформаційна система погодження внутрішніх документів

Курсова робота з дисципліни «Кросплатформене програмування», варіант 25
(група 202-TH, Федоров Назар Олексійович).

## Призначення

Система веде облік документів, авторів, рецензентів і запитів на погодження.
Для кожного запиту сервер обчислює інтегральний показник пріоритету
`I = 0,40·F1 + 0,35·F2 + 0,25·F3` (усі фактори — від 0 до 100):

- **F1** — близькість строку: `max(0; min(100; (30 − днів до строку) / 30 · 100))`;
- **F2** — критичність документа (0..100);
- **F3** — залежні процеси: `min(100; кількість / 10 · 100)`.

Життєвий цикл запиту: `DRAFT → SUBMITTED → REVIEW → APPROVED`. Пропуски станів,
повернення назад і переходи після `APPROVED` сервер відхиляє.

## Технології

Java 21, Maven, JavaFX 21 (клієнт), Servlet 4.0 (`javax.*`, Tomcat 9.x),
Jackson (JSON), MySQL 8 + JDBC (лише сервер), JUnit 5, `java.util.logging`.

## Архітектура

```
JavaFX → HttpApprovalClient → HTTP/JSON → Servlet → Service → DAO → JDBC → MySQL
```

- SQL і JDBC — тільки в DAO сервера; клієнт до БД не звертається.
- Бізнес-правила (валідація, F1–F3, I, переходи станів) — у Service / `RiskCalculator`.
- Клієнт виконує лише технічну перевірку формату (поля форм, CSV).

## Структура репозиторію

```
database.sql        скрипт створення БД і початкових даних
docs/               схеми (архітектура, БД, життєвий цикл)
server/             Maven-модуль, WAR для Tomcat 9.x (+ тести в src/test)
client/             Maven-модуль, JavaFX-клієнт (+ sample-data/documents.csv)
```

## Підготовка бази даних

1. Запустіть MySQL 8 на `localhost:3306`.
2. Виконайте скрипт (він перестворює базу `document_approval`):
   `mysql -u root -p < database.sql`
3. Параметри підключення (`URL`, `USER`, `PASSWORD`) задано в `server/src/main/java/ua/edu/nupp/kpp/server/DBUtil.java`;
   за потреби змініть їх перед збіркою (паролі в репозиторій не додавайте).

## Запуск сервера

```
cd server
mvn clean package
```

Скопіюйте `server/target/document-approval-server.war` у каталог `webapps` Tomcat 9.x
і запустіть Tomcat. Перевірка: `http://localhost:8080/document-approval-server/documents`
має повернути JSON-масив.

## Запуск JavaFX-клієнта

Клієнт запускається з каталогу `client` (CSV читається за відносним шляхом
`sample-data/documents.csv`):

```
cd client
mvn clean javafx:run
```

## Тестування

Модульні тести JUnit 5 не потребують Tomcat і MySQL:

```
cd server
mvn test
```

Тести покривають `RiskCalculator` (F1, F2, F3, I, некоректні фактори),
дозволені й заборонені переходи станів, валідацію документів, авторів, рецензентів
і довжину коментаря.

## Імпорт документів із CSV

У вкладці «Документи» натисніть «Імпортувати CSV». Файл `client/sample-data/documents.csv`
(розділювач `;`, UTF-8, перший рядок — заголовок):

```
author_id;title;doc_type;deadline_date;criticality;dependent_processes
```

Імпорт виконує JavaFX `Task` (`ImportDocumentsTask`) у фоновому потоці: інтерфейс не
блокується, `ProgressBar` і підпис показують прогрес, кнопка «Скасувати» зупиняє
імпорт між рядками. Task лише читає файл і надсилає рядки через HTTP-клієнт;
запис у MySQL виконує сервер.

Обробка помилок:

- некоректний рядок CSV (кількість стовпців, формат числа) — імпорт завершується
  помилкою з номером рядка **до** першого запиту, у БД нічого не потрапляє;
- помилка сервера (наприклад, автора не існує) — імпорт зупиняється, у повідомленні
  вказано номер рядка і скільки записів уже передано;
- відсутній файл — повідомлення про помилку, вікно залишається робочим.

Перед повторним імпортом після збою видаліть уже створені документи у вкладці «Документи».

## Журналювання і безпека

Журнал ведеться через `java.util.logging`. Файли `*.log`, `target/`, `.idea/`, `.env`
виключено через `.gitignore`. Усі SQL-запити параметризовані (`PreparedStatement`).
